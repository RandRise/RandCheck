# AED-only invoice check — October 12, 2026

## Scope and acceptance

Rand approved AED only to keep the product simple. No FX service, rates, scheduler,
new dependency, schema migration, permission change or data cleanup is introduced.
This is a bounded application entry gate for new saved InvoicePurchaseOrder
evaluations. Existing `invoice-po-1.0` and legacy rules are unchanged. A new policy
version is unnecessary: accepted inputs produce the same calculations.

The backend loads exact pinned completed reviews once, validates them before
`BeginEvaluation`, then uses those same sources for snapshots. Both documents need
one header currency of type Currency, latest Confirmed/Corrected decision, machine
origin and the same first page quote used by the engine. Missing, unchecked,
cleared, added, duplicate, wrongly typed and foreign currencies cannot pass.
No normalized fallback, currency conversion or silent confirmation occurs. Explicit
source corrections remain possible; they are reviewed corrections, not conversion.

Rejected requests must not change case ETag, status, run count or save anything.
Completed reviews, earlier results, original source values and audit remain readable.
New evaluations of older non-AED saved pairs can be refused. Retained legacy tools
remain compatible. Document AED does not make missing/foreign tax currency usable.

## Runtime and manual checks

The active synthetic preview was not restarted or reset: its in-memory document
list must be preserved. UI source can refresh, but its already-loaded simulated
backend still predates the gate. Automated preview tests load the changed fixtures
in disposable processes. Neither is proof of real .NET integration or manual acceptance.

After running the updated .NET app:

1. Open Invoice checks and read the AED-only note. Compare two checked AED documents.
2. Try a pair with a non-AED or unverified currency. Expect a clear message and no
   new result. Do not change a foreign amount to AED to get past this check.
3. Reopen the saved review and an earlier result. Their values should be unchanged.

No manual pass is claimed. Supplier identity, G02/G03, Python organization, live
identity, OCR, export and deployment gaps remain separate. The guide distinguishes
the approved gate from unapproved dashboard and role proposals.
