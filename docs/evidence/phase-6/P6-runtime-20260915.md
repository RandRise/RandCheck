September 15, 2026. This report accompanies the
[runtime baseline](../../design/phase-6-runtime-baseline.md). Artifacts are under
`outputs/phase-6/runtime-20260915`.

**1,338 distinct checks pass:** 938 backend (including 44 PostgreSQL), 64 browser
and 336 Python. The 330 Python application cases also pass inside the patched Linux
image; that repeat is not added to the distinct count. Browser and documentation
builds, TypeScript, lint and whitespace checks pass.

## Regression and evidence

The full backend build passes with zero warnings and errors. The non-PostgreSQL suite
passes 894 tests across Domain, Application, Infrastructure, API and Architecture.
Browser tests pass 61 Vitest cases plus three request-concurrency cases. Python
application/native groups pass 330 plus one test. These are executed checks, not a
claim that the full deployment or every historical fixture group was tested here.

All 44 selected PostgreSQL cases pass after replacing an outdated migration-count
assertion (16 versus the current 19). The corrected rollback/reapply run supersedes
that one case from the initial 43-pass/one-failure run. Counts use TRX test ID plus
display name because 19 distinct Domain theory cases share parent IDs in this adapter.
No migration implementation changed.

The test-runner upgrade exposed jsdom's missing `Blob.text()` method. The download
test now reads the same bytes through FileReader and retains its original-content
assertion. Production download code is unchanged. ESLint now excludes the existing
`.next-*` generated builds as well as `.next` to keep validation scoped to source.
Two narrowly documented effect-style exceptions preserve retention controls' existing
loading/reset behavior before asynchronous refetches; those flows were not rewritten.

The loaded native SQLite library reports 3.53.4. The tested production Python image
ID is `sha256:073e501d5f54d131593bb361a32382a7c33042743c23a9a1fd7920543ee6efcd`.
Its OCI base digest, installed packages and package audit are recorded separately.
The test-only derivative installs development/embedding extras; those are not added
to the deployed image. Both container test runs mount source/fixtures read-only and
disable network access. No golden output was regenerated.

Raw TRX results, build/test logs, before/after audit JSON, package inventories,
official runtime metadata/checksums and the old-host refusal are retained. Initial
failed build/test attempts are diagnostic history, superseded by final results.
Final totals and unresolved checks are recorded in `verification.json`.

## Deployment boundary

Package audit success is distinct from OS, interpreter and container security. Real
identity/TLS, scanner deployment, shared keys/ACLs, backup recovery and enterprise
activation remain open. The repository preflight still requires live evidence.
No retained database migration, source cleanup, paid provider call or commit occurred.
All 34 retained-table fingerprints match. Windows Python remains 3.11.9 for the local
development environment; enterprise interpreter verification uses the patched Linux
image. Python 3.11.9 is the last upstream Windows installer in that branch, so moving
the Windows environment to a maintained interpreter requires a separate migration.
The historical fixture generator's exact old dependencies are unchanged and excluded
from the clean application/image audit claims. OS/native vulnerability scanning,
API/browser container rebuild verification and actual deployment activation remain open.
