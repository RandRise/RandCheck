[inventory](P8-ci-source-inventory.json)). Corrected Python and legacy-fixture checks
used `outputs/ci-source/81f785689247` (823 files;
[inventory](P8-ci-python-source-inventory.json)). Backend/browser code and package
inputs were compared and remain unchanged across those reruns. Final documentation
and Git line-ending rules are subsequent delivery-only changes.

Final delivery snapshot `d0f05f65453d` also passes the source-ownership checks,
workflow lint and documentation build. The latter used the project-selected Node
24.21.0 through `tools/use-project-runtimes.ps1` in the isolated Windows copy;
its [build receipt](ci-checks-20260916/final-docs-build.json) records completion.
A Docker image lookup failed before starting a container, so this final docs-only
check used the host runtime. The image inventory subsequently confirmed the cached
CI images remained present. The build reported only the documented chunk-size warning.

database connection. The private PostgreSQL service has no host port and stores
data in tmpfs. Backend tests share its network namespace to satisfy the existing
loopback/TLS and crash-probe guards. Tests have no external network route; build
downloads, workflow-linter downloads and fresh advisory queries are separate.
No application security guard was disabled or weakened.

The retained database fingerprint SHA-256 is
`06c07f7f05eb9d20a7ceb561d43821414427bd79d0453e170a65ae41132c7549`.
Source copies, build cache and raw logs remain under ignored `outputs/ci-source/`.

and redirected paths. Git attributes preserve shell line endings and frozen fixture

## Failed attempts and corrections

- The first image omitted a compile-time JSON fixture. CLI projects also needed
  explicit solution membership and copied entry-point/runtime files for clean
  Release child-process tests. These packaging issues were corrected.
- The first PostgreSQL attempt correctly rejected the non-loopback `Host=db`
  connection. The corrected namespace uses loopback; Python fixture servers and
  repository-root markers were included, and the exact schema assertion gained
  four existing Phase 6 tables. The superseded container was stopped and its
  project cleaned up. All 433 PostgreSQL tests then passed.
- The first Python selection found seven failures/errors caused by ignored
  synthetic inputs. The next selection passed 330 application cases but found
  another ignored native invoice. Five unchanged, hash-pinned synthetic inputs
  are now available from `samples/`; the Phase 3 smoke report is freshly generated.
  Expected hashes, extraction JSON, assertions and OCR goldens were not changed.
  The final Python and fixture groups both pass, with successful cleanup.
- An isolation probe initially misread Docker's empty-string tmpfs metadata.
  Checking the mount key and kernel mount table confirmed the intended storage.

The initial `all` run is retained as **failed**, not relabelled. Its passing backend
and web stages are combined with successful targeted Python/fixture reruns and fresh
audits. Every declared group is covered; there was no new single all-green `all` run.
