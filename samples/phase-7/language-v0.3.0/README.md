The nine v0.2.0 cases are unchanged. Three additional mixed-language cases vary
identifiers, amounts and payment duration; reverse the crowded totals row; and
include genuine English payment wording under an Arabic label. All are fictional
project-authored data with the same provenance as v0.2.0.

Expected values were fixed and text-checked before running image OCR. This small
extension checks regressions in the targeted line retry; it is not a blind
benchmark or an estimate of real-invoice accuracy. Keep original v0.2.0 results
separate from the added cases and preserve every failed receipt.
